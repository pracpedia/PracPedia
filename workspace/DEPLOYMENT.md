# Deploying PracPedia to Vercel

This guide walks you through deploying PracPedia to Vercel from scratch — no prior Vercel experience needed.

**Total time:** ~15 minutes
**Cost:** Free (Vercel Hobby tier + Neon free tier + Vercel Blob free tier)

---

## Prerequisites

- A [GitHub](https://github.com) account (free)
- A [Vercel](https://vercel.com) account (free — sign up with GitHub)
- A [Neon](https://neon.tech) account (free — serverless Postgres)
- Your PracPedia code pushed to a GitHub repo

---

## Step 1 — Push Your Code to GitHub

```bash
# In your PracPedia project directory:
git init
git add .
git commit -m "Initial PracPedia commit"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/pracpedia.git
git push -u origin main
```

> ⚠️ Make sure `.env` is in `.gitignore` (it is by default). Never commit secrets.

---

## Step 2 — Create a Neon Postgres Database

SQLite doesn't work on Vercel (ephemeral filesystem). You need a real Postgres database.

1. Go to [neon.tech](https://neon.tech) → Sign up (free, no credit card)
2. Click **Create New Project**
3. Name it `pracpedia` → select the region closest to your users
4. Copy the **Connection String** — it looks like:
   ```
   postgresql://neondb_owner:npg_password@ep-cool-name-123456.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
5. Save this — you'll paste it into Vercel in Step 4

---

## Step 3 — Switch Prisma to Postgres

Before deploying, switch the Prisma schema from SQLite to Postgres:

```bash
# In your local project:
bun run db:use-postgres    # copies schema.postgres.prisma → schema.prisma
```

This changes `provider = "sqlite"` → `provider = "postgresql"` in `prisma/schema.prisma`. The models stay identical — no data migration needed since you're starting fresh on Neon.

Commit this change:
```bash
git add prisma/schema.prisma
git commit -m "Switch to Postgres for Vercel deployment"
git push
```

---

## Step 4 — Create a Vercel Project

1. Go to [vercel.com](https://vercel.com) → Sign up with GitHub
2. Click **Add New...** → **Project**
3. Import your `pracpedia` repo
4. Vercel auto-detects Next.js — leave the build settings as default:
   - **Framework Preset:** Next.js
   - **Build Command:** `next build` (Vercel handles the standalone output automatically)
   - **Output Directory:** `.next` (auto-detected)

---

## Step 5 — Set Environment Variables on Vercel

In the Vercel project setup screen (or later under Settings → Environment Variables), add each of these:

| Name | Value | Where to get it |
|---|---|---|
| `DATABASE_URL` | `postgresql://neondb_owner:...@ep-xxx.neon.tech/neondb?sslmode=require` | From Step 2 (Neon dashboard) |
| `JWT_SECRET` | (generate a random 32+ char string) | Run `openssl rand -hex 32` in your terminal |
| `PRACPEDIA_TEST_PASSWORDS_VISIBLE` | `false` | Hardcoded — disable in production |
| `BLOB_READ_WRITE_TOKEN` | (from Vercel Blob — Step 6) | From Vercel Storage tab |
| `SENTRY_DSN` | (optional — from Sentry) | Skip if not using Sentry |

> ⚠️ **Critical:** Set `JWT_SECRET` to a strong random string. If you leave it as the default, the app will refuse to start in production (throws `FATAL: JWT_SECRET...`).

> ⚠️ **Critical:** Set `PRACPEDIA_TEST_PASSWORDS_VISIBLE` to `false`. Otherwise the `/api/credentials` endpoint exposes system info.

**For each env var:**
1. Enter the Name and Value
2. Select all environments: **Production**, **Preview**, **Development**
3. Click **Save**

---

## Step 6 — Create a Vercel Blob Store (for image uploads)

Without Blob storage, images are stored as base64 in the database — this bloats the DB and slows down queries.

1. In your Vercel project dashboard → **Storage** tab
2. Click **Create Blob Store**
3. Name it `pracpedia-blob`
4. Select the same region as your Neon database
5. Click **Create**
6. Vercel auto-adds `BLOB_READ_WRITE_TOKEN` to your environment variables — no manual setup needed

---

## Step 7 — Initialize the Database

After the first deploy, you need to create the database tables and seed demo data.

### Option A: Via Vercel CLI (recommended)

```bash
# Install Vercel CLI
npm i -g vercel

# Login + link to your project
vercel login
vercel link    # select your pracpedia project

# Pull production env vars to .env.local
vercel env pull .env.local --environment=production

# Push the Prisma schema to your Neon database
bunx prisma db push

# Seed demo data
bunx tsx prisma/seed.ts

# Clean up
rm .env.local
```

### Option B: Via Neon's SQL Editor

1. Go to your Neon dashboard → **SQL Editor**
2. Run the SQL generated by `prisma db push` (you can get this by running `bunx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script` locally)
3. For seeding, run the seed script locally with `DATABASE_URL` set to your Neon connection string

---

## Step 8 — Deploy

1. In Vercel, click **Deploy**
2. Wait 2-3 minutes for the build to complete
3. Vercel gives you a URL like `https://pracpedia-xxx.vercel.app`
4. Click **Visit** to see your live app

### Verify the deployment:

```bash
# Replace YOUR_URL with your Vercel URL
curl https://YOUR_URL/api/health
# Should return: {"status":"ok","timestamp":"...","latencyMs":1,"env":"production"}

# Test login
curl -X POST https://YOUR_URL/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@gallery.com","password":"admin123"}'
# Should return: {"token":"...","user":{...}}
```

---

## Step 9 — Set Up a Custom Domain (Optional)

1. In Vercel → your project → **Settings** → **Domains**
2. Enter your domain (e.g. `pracpedia.com`)
3. Vercel shows you the DNS records to add:
   - **A record:** `@ → 76.76.21.21`
   - **CNAME record:** `www → cname.vercel-dns.com`
4. Add these records in your domain registrar (GoDaddy, Namecheap, Cloudflare, etc.)
5. Wait 5-30 minutes for DNS propagation
6. Vercel auto-provisions HTTPS via Let's Encrypt

---

## Step 10 — Set Up Sentry (Optional but Recommended)

1. Go to [sentry.io](https://sentry.io) → Sign up (free tier = 5,000 errors/month)
2. Create a project → select **Next.js**
3. Copy the **DSN** (looks like `https://xxx@oXXX.ingest.sentry.io/XXX`)
4. In Vercel → Settings → Environment Variables:
   - `SENTRY_DSN` = your DSN
5. Redeploy

> Note: Full Sentry integration with source maps requires `@sentry/nextjs` package and `sentry.client.config.ts`. See [Sentry's Next.js docs](https://docs.sentry.io/platforms/javascript/guides/nextjs/).

---

## Post-Deploy Checklist

After your app is live, verify each of these:

- [ ] **Health check works:** `https://YOUR_URL/api/health` returns `{"status":"ok"}`
- [ ] **Login works:** Can log in with `admin@gallery.com` / `admin123`
- [ ] **Database persists:** Create a subject, redeploy, verify the subject still exists
- [ ] **Image uploads work:** Upload an image to a folder, verify it appears
- [ ] **Chat works:** Post a message in classroom discussion, verify it appears in real-time
- [ ] **Rate limiting works:** 6 rapid login attempts → 6th returns 429
- [ ] **Security headers present:** Check [securityheaders.com](https://securityheaders.com/?q=YOUR_URL)
- [ ] **HTTPS works:** Visit `https://YOUR_URL` — should auto-redirect from HTTP
- [ ] **Test mode OFF:** `PRACPEDIA_TEST_PASSWORDS_VISIBLE=false` → `/api/credentials` returns 404

## How Vercel Handles the App

| Component | How it works on Vercel |
|---|---|
| **Next.js pages** | Static pages are CDN-cached; dynamic pages are serverless functions |
| **API routes** | Each route becomes a serverless function (cold start ~100ms) |
| **Database** | Neon Postgres (serverless, auto-scaling, free tier) |
| **Image storage** | Vercel Blob (CDN-backed, auto-optimized) |
| **Auth** | JWT stored in localStorage, verified via Web Crypto API in serverless |
| **Chat** | Long-polling (20s max per request, auto-reconnects) |
| **AI Academy** | BYOK — each user's Gemini key is sent per-request, no server-side key needed |
| **Build** | `next build` produces standalone output, Vercel auto-detects |

---

## Vercel Limitations to Be Aware Of

| Limitation | Impact | Mitigation |
|---|---|---|
| **Serverless timeout** (10s on Hobby, 60s on Pro) | Long API calls may time out | AI Academy routes have fallback templates; chat uses 20s long-poll |
| **No WebSocket support** | Can't use Socket.io for real-time chat | Using long-polling instead (works on serverless) |
| **Ephemeral filesystem** | Can't write files to disk | Using Vercel Blob for image storage |
| **Cold starts** (~100ms) | First request after idle is slower | Vercel auto-warms popular routes |
| **Function size limit** (50MB) | Large dependencies may exceed | Prisma client + node_modules are within limit |
| **Env var size limit** (4KB per var) | Very long secrets may fail | JWT_SECRET is 64 chars — well within limit |

## Troubleshooting

### "FATAL: JWT_SECRET environment variable is not set"
→ You forgot to set `JWT_SECRET` in Vercel env vars. Go to Settings → Environment Variables, add it, and redeploy.

### "Database connection failed" / Prisma errors
→ Check that `DATABASE_URL` is set correctly and points to your Neon database (must start with `postgresql://`). Make sure `?sslmode=require` is at the end.

### "Module not found: @vercel/blob"
→ Run `bun add @vercel/blob` locally, commit `package.json`, and push. Vercel installs deps from `package.json` during build.

### Images don't upload / show broken
→ Check that `BLOB_READ_WRITE_TOKEN` is set in Vercel env vars. Without it, images fall back to base64 (works but bloats the DB).

### Build fails with TypeScript errors
→ The build does NOT ignore TS errors (we removed `ignoreBuildErrors`). Fix the errors locally with `bun run build` before pushing.

### Chat doesn't update in real-time
→ Long-polling has a 20s max wait. If no messages arrive, it reconnects after 20s. New messages should appear within 1-2 seconds of being posted. If not, check the browser console for errors.

### "Too many login attempts" (429)
→ The rate limiter allows 5 logins per minute per IP. Wait 60 seconds or use a different IP. This is intentional — it prevents brute force attacks.

### Need to reset the database?
→ In Neon dashboard, you can drop all tables and re-run `prisma db push` + `prisma db seed` via Vercel CLI (see Step 7).

## Quick Deploy Summary (TL;DR)

```bash
# 1. Push to GitHub
git push origin main

# 2. Switch to Postgres
bun run db:use-postgres
git add . && git commit -m "Use Postgres" && git push

# 3. On Vercel: Import repo, set env vars:
#    DATABASE_URL=postgresql://...neon.tech/...
#    JWT_SECRET=<openssl rand -hex 32>
#    PRACPEDIA_TEST_PASSWORDS_VISIBLE=false
#    BLOB_READ_WRITE_TOKEN=<auto-set when you create Blob store>

# 4. Deploy on Vercel

# 5. Initialize DB (via Vercel CLI):
vercel env pull .env.local --environment=production
bunx prisma db push
bunx tsx prisma/seed.ts
rm .env.local

# 6. Visit your live URL!
```

That's it. Your PracPedia is now live on the internet with HTTPS, CDN, auto-deploys on every git push, and zero server maintenance. 🚀
